# PLAN

## Goal

Google Sheets の同一ページ内で、現在のシートの直前にアクティブだったシートを追跡し、Sheet Finder を開いたときの初期選択にする。
有効な直前シートがない場合は、現在のシートを初期選択する。

## Current Findings

- `src/overlay-state.js` は、オーバーレイを開くたびに検索文字列と選択位置を初期化し、常に `selectedIndex: 0` にしている。
- `src/overlay.js` はアダプターから `currentName` を受け取り、現在シートの表示には利用しているが、直前シートの履歴は保持していない。
- `src/sheets-adapter.js` には DOM から現在シート名を取得する内部処理があるが、作成したアダプターの公開APIには含まれていない。
- `src/content.js` はすでに Google Sheets の DOM を `MutationObserver` で監視しているが、オーバーレイを閉じている間の現在シート変更を履歴として記録していない。
- `test/overlay-state.test.js` は、オーバーレイを開いたときに先頭結果を選択する現行動作を検証している。
- `README.md` は検索・移動操作を説明しているが、初期選択や履歴の対象範囲は説明していない。
- 変更前の `npm test` は15件すべて成功している。
- リポジトリには既存の実装計画規約・計画ファイルがないため、本ファイルを `docs/plans/plan_YYYYMMDDHHMMSS.md` 規約で作成する。
- 未追跡の `.agents/` はユーザー所有のローカル指示であり、実装対象に含めない。

## Decisions

- Sheet Finder 経由の移動だけでなく、シートタブのクリックや Google Sheets 側の操作を含む、同一ページ内で検出可能なすべてのシート移動を履歴対象にする。
- 履歴はページ内のメモリーにだけ保持し、ページ再読み込み、別スプレッドシート、別タブ、ブラウザ再起動をまたいで永続化しない。
- 有効な直前シートが存在しない場合は、現在のシートを初期選択する。
- 直前シートが削除・改名されるなど、取得した候補一覧に存在しない場合も現在のシートへフォールバックする。
- Google Sheets API、OAuth、新しい Chrome 拡張権限、ストレージ権限は追加しない。
- 入力後の検索順位、検索開始時の選択リセット、上下キー、Enter、クリック、IME変換中のEnter抑止は維持する。

## Open Questions Resolved

1. 履歴として追跡する移動範囲:
   ページ内で検出可能なすべてのシート移動を対象にする（選択肢B）。
2. 有効な直前シートがない場合の初期選択:
   現在のシートを選択する（選択肢B）。

## Scope

### In scope

- 現在シートと直前シートをページ内で追跡する状態遷移。
- Google Sheets のDOMから現在シート名を軽量に取得できるアダプターAPI。
- オーバーレイを閉じている間を含む、検出可能なシート変更の通知と履歴更新。
- オーバーレイの空検索結果における初期選択の決定。
- 直前シートがない、または候補に存在しない場合の現在シートへのフォールバック。
- 状態、コンテンツ監視、アダプター、初期選択に対する自動テスト。
- README の利用仕様と手動確認項目の更新。

### Non-goals

- ページ再読み込みやブラウザ再起動をまたぐ履歴永続化。
- 複数スプレッドシート・複数タブ間の共有履歴。
- Google Sheets API、OAuth、追加権限の導入。
- 検索アルゴリズムや検索順位の変更。
- Google Sheets がDOMへ反映しない操作まで保証すること。
- Issue #1 と無関係なUI刷新または広範なリファクタリング。

## Steps

1. `src/overlay-state.js` に、現在シートを記録し、値が実際に変わった場合だけ従来の現在値を直前値へ移す純粋な状態遷移を追加する。同一シートの重複通知、空値、初期観測では誤った履歴を作らない。
2. 初期選択を決める純粋な処理を追加する。空検索の候補に直前シートがあればその位置を選び、なければ現在シート、そのどちらもなければ安全な既存フォールバックを使う。比較は既存の正規化規則と整合させる。
3. `src/sheets-adapter.js` から現在シート名の読み取りを公開し、全シートメニューを開かずに履歴監視から利用できるようにする。既存の一覧取得と移動動作は維持する。
4. `src/overlay.js` に履歴更新用の小さな公開入口を設け、一覧取得時にも最新の現在シートを状態へ反映してから初期選択を計算する。検索入力後は従来どおり先頭一致へ選択を戻す。
5. `src/content.js` のDOM監視を拡張し、ページ初期化時と検出可能な選択変更時に現在シートを読み取ってオーバーレイ状態へ渡す。シートの `aria-selected` や選択クラスの変化を捕捉しつつ、既存の一覧更新通知のデバウンスと拡張コンテキスト消失時の安全性を維持する。全シート一覧の取得を監視ループ内では行わない。
6. `test/overlay-state.test.js` に、初期観測、A→B、重複通知、B→A、直前シート優先、直前シート不在時の現在シートフォールバックを追加する。
7. `test/sheets-adapter.test.js` と `test/content.test.js` に、現在シート公開API、オーバーレイを閉じた状態での直接操作追跡、無関係なDOM変化や無効化された拡張コンテキストで例外を出さないことを追加する。必要ならオーバーレイコントローラーの初期選択を対象とする小さなテストを新設する。
8. `README.md` に、直前シートが初期選択されること、履歴がページ内に限定されること、履歴がなければ現在シートを選ぶこと、および対応する手動確認項目を追記する。
9. 完全な自動テストと差分確認を実施し、未追跡の `.agents/` や無関係なユーザー変更が変更されていないことを確認する。

## Validation

- `npm test` を実行し、既存テストと追加テストをすべて成功させる。
- 自動テストで少なくとも次を検証する。
  - 初回観測では直前シートを作らず、現在シートが初期選択される。
  - AからBへ移動後、Bで開くとAが初期選択される。
  - その状態でAへ戻った後、Aで開くとBが初期選択される。
  - 同じ現在シートの重複通知で履歴が反転・上書きされない。
  - 直前シートが候補一覧から消えた場合、現在シートが選択される。
  - オーバーレイを閉じている間の直接操作でも履歴が更新される。
  - 検索文字を入力すると既存どおり検索結果の先頭へ選択が移る。
  - IME変換中のEnter抑止、上下キーの循環、クリック移動が維持される。
  - 拡張コンテキスト消失時と現在シート未検出時に例外を出さない。
- 可能な実ブラウザ確認では、同一スプレッドシートで A→B→スイッチャー、B→A→スイッチャー、シートタブ直接操作、削除・改名後のフォールバックを確認する。実ブラウザ確認が環境上できない場合は、その旨を残存リスクとして報告する。

## Risks

- Google Sheets の選択状態を表すDOM属性・クラスが変更されると、直接操作の履歴追跡が機能しなくなる可能性がある。
- MutationObserver の対象を広げすぎると高頻度に処理されるため、現在シート名の軽量な比較と既存デバウンスを使い、一覧取得やメニュー操作を監視処理から分離する必要がある。
- Google Sheets が短時間に複数の中間DOM状態を作る場合、空値や同一値を履歴として扱うと誤った直前シートになる可能性がある。
- オフスクリーンの選択タブやローカライズされたDOMで現在シートが取得できない場合があるため、履歴を破壊せず、一覧取得時の現在シートと安全なフォールバックを併用する。
- 実ブラウザのGoogle Sheets DOMに対する自動E2E環境はないため、単体テストだけでは実DOMとの完全な互換性を保証できない。
